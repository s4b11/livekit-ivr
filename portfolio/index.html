03About

I like owning a system end to end: drawing the architecture, designing the APIs and data, building the agents and automations that do the work, and putting a clear interface on top — then measuring it, so problems show up in data instead of in production.

A

Design first

Diagrams, contracts and failure modes before code, so the system has a shape everyone can see.

B

Measure, then fix

Timing, logs and evals first. A fix only counts when the numbers move.

C

Automate the boring parts

Workflows, agents and CI/CD that do the repeatable work, with a human approving what matters.
